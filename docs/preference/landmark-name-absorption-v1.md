# 랜드마크 이름 흡수 v1

인지도 매칭이 **남의 장소 이름을 자기 언급으로 세던 문제**를 계측하고 고쳤다.
흡수율 14.5% → 6.9%, R\|cat 0.538 → 0.572, MRR 0.747 → 0.778. 적재 증가 없음.

전제 — [popularity-saturation-and-pool-size-v1.md](popularity-saturation-and-pool-size-v1.md) §6 에서
"경주 1위가 `동양백반 경주황리단길 본점`" 으로 남겨 둔 항목이다.

## 1. 통로는 `matchKeys` 의 토큰 폴백이었다

`NaverPopularityIndex` 는 매칭 키를 세 개 순서대로 시도한다 — ① 전체명 ② 기관 수식어를 뗀 코어
③ **등록명 토큰 중 긴 것**. ③은 장식적 등록명을 살리려고 넣은 것이다
('대구 서문시장 & 서문시장 야시장' 은 통째로는 코퍼스에 0회, 토큰 '서문시장' 으로는 13회).

그런데 ③이 상호·부속시설에 박힌 **남의 이름**도 그대로 살린다.
`동양백반 경주황리단길 본점` 은 전체명 0회지만 토큰 `경주황리단길` 로 랜드마크 언급을 통째로 가져간다.

## 2. 먼저 얼마나 일어나는지 셌다

`measure-name-absorption.ts` 를 새로 만들었다. 판정법 — **이름의 공백을 지우면 토큰이 하나가 되어
토큰 폴백이 꺼진다.** 그 값(전체명 언급)이 0 인데 원래 이름의 언급이 0 보다 크면 그 점수는 전부
토큰에서 온 것이다.

골든셋 상위 16 전체(248건) 계측 결과 **36건(14.5%)**. 그리고 예상과 달랐다 —
**프랜차이즈 문제가 아니었다**: attraction 30 · restaurant 4 · cafe 2.

가장 큰 덩어리는 **부속 시설이 모시설을 물려받는 것**이었다 (전주 케이스 10/16):

```
전주수목원 무궁화화원1 · 남부수종원 · 일반수목원 · 로드덴드론 가든 · 교육홍보관
  → 다섯 개가 전부 '전주수목원' 20회를 나눠 가짐 (각 popularity 0.98)
한옥마을 선비문화관 · 한옥마을 예술공동체        → '한옥마을' 170회 (각 1.00)
광주광역시 서구문화원 · 부산광역시 119안전체험관   → 행정구역명 언급
설악산국립공원 자동차야영장                    → '설악산국립공원' 10회
```

이것이 [popularity-saturation-and-pool-size-v1.md](popularity-saturation-and-pool-size-v1.md) §4 에서
풀 배수 40 의 **유일한 악화였던 전주 0.57→0.43 의 원인**이다. 풀을 키우니 수목원 부속시설이 더 들어왔다.

## 3. 규칙 — 앞머리 토큰은 매칭 키가 아니다

흡수하는 토큰의 공통점이 선명했다: **전부 이름의 앞머리**다. 한국어 장소명에서 앞에 붙는 토큰은
그 장소의 정체성이 아니라 **담고 있는 것**(행정구역·모시설)이고, 정체성은 뒤에 온다.
폴백이 원래 살리려던 '서문시장' 은 앞머리가 아니라 규칙에 안 걸린다.

### 예외 하나 — 장식 구분자가 있으면 앞머리가 정체성이다

앞머리 배제만 넣었을 때 서울이 0.30 → 0.20 으로 내려갔다. 원인은 `롯데월드타워&롯데월드몰` 이다 —
카탈로그가 `&` 로 이어 붙여 등록한 이름이라 앞머리가 곧 정답 `롯데월드타워` 였다.
그래서 **공백이 아닌 구분자(`&`·`,`·`·`·괄호)가 있는 이름은 예외**로 뒀다. 서울 회귀가 사라졌다.

### 곁에서 드러난 것 — 괄호가 전체명 매칭을 죽인다

광주가 0.70 → 0.60 으로 내려갔는데, 잃은 건 `사직공원` 이었다. 파 보니 **가짜 크레딧**이었다 —
정답으로 인정받던 후보가 `사직공원 전망타워`(공원이 아니라 전망대)였고, 규칙이 그 흡수를 끊은 것이다.
규칙은 맞았다.

다만 그 과정에서 진짜 행이 왜 안 올라오는지가 드러났다. 카탈로그는 동명이지를 가르려고
`사직공원(광주)` 로 등록하는데 블로그는 괄호 없이 쓴다 — **전체명 매칭이 0 이라 실제 정답이
인지도 하한(0.15)을 맞고 있었다.** 괄호를 뗀 키를 하나 더 시도하게 했다.

## 5. 남은 것

- `부석사 [유네스코 세계유산]` 류는 아직 흡수한다. 대괄호가 장식 구분자라 예외로 빠지는데,
  정작 앞머리 `부석사` 는 3글자라 `MIN_CORE_LENGTH`(4)에 걸려 토큰 목록에서 빠지고
  `유네스코`·`세계유산` 만 남는다. 예외 규칙과 길이 컷이 맞물린 구멍이다
- 조밀 적재 재판단은 끝났다 — 선발을 고친 뒤에도 손해다
  ([kakao-category-search-ceiling-v1.md](kakao-category-search-ceiling-v1.md) §6). 인지도 커버리지
  게이트가 풀 크기에 민감하다는 잠복 위험도 거기 기록했다
- `daegu-nostalgic`(0.31)·`seoul-city-nightview`(0.30)·`busan-beach` R@10(0.23)은 여전히 낮다.
  셋 다 코퍼스가 그 지역을 잘 못 담는 케이스(대구 1.3%·서울 6.0%)라 다른 접근이 필요하다
- **하네스 매칭은 고치지 않는 게 맞다** (측정 후 결론). 적중 83건 중 부분일치가 유일한 크레딧인
  건 10건이고 그중 9건이 정당하다(`경주 교촌마을`·`사직공원(광주)`·`롯데월드타워&롯데월드몰`…).
  가짜는 `소백산꽃차이야기` 1건뿐이라 접두/완전일치로 바꾸면 9건을 죽여 1건을 잡는다.
  [kakao-source-enrichment-v1.md](kakao-source-enrichment-v1.md) §9 의 처방은 그래서 철회했다
- 그 1건은 하네스가 아니라 **카탈로그 구멍**이다 — `소백산` 자체가 없고 상호만 있다
  (`소백산식당`·`소백산풍기인삼순대`…). `자만벽화마을`(카카오 `category_group_code` 빈 값)과 같은 부류로,
  **키워드 검색 적재 경로**가 있어야 잡힌다
