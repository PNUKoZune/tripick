# 후보 풀의 식음 상한 v1

"질의 의도가 랭킹에 반영되지 않는다"를 파고든 결과다. 결론부터 — **의도 분류기를 붙일 문제가 아니었다.**
후보 풀에 식음(음식점·카페) **하한만 있고 상한이 없던 것**이 원인이고, 상한을 넣자 오래 부진하던
`daegu-nostalgic` 이 R\|cat 0.23 → 0.31 로 올랐다. 나빠지는 케이스는 없었다.

전제 — [kakao-category-search-ceiling-v1.md](kakao-category-search-ceiling-v1.md) §4 에서 조밀 적재가
busan-beach 를 0.00 으로 무너뜨린 원인 조사의 후속이다.

## 1. `intent` 는 파이프라인에 안 들어간다

골든셋 케이스에 `intent` 필드가 있다 — "바다·힐링 취향의 부산 — 해변이 상위에 와야 한다".
그런데 **읽는 코드가 없다.** `grep -rn "intent" src/planner/` 가 0건이다. 사람이 읽는 설명일 뿐이다.

파이프라인이 실제로 받는 건 `destination` 과 `tasteTags` 다. busan-beach 의 질의문은 이렇게 만들어진다:

```
destination:부산 | event:initial | taste:seafood, healing, beach
```

`seafood` 가 질의에 그대로 들어간다. 즉 **횟집이 해변과 같은 자리를 놓고 경쟁하는 게 설계상 정상**이다.
의도를 따로 분류해 봐야, 취향 태그에 음식 항목이 있는 한 음식 후보는 계속 정당하게 올라온다.

## 2. 진짜 원인 — 하한만 있고 상한이 없었다

`selectTopDiverse` 는 종류별 **최소 보유량**(`POOL_MIN_PER_KIND = 2`)만 보장한다. 상한은 없다.
조밀 적재한 부산에서 상위 16 중 14가 횟집·카페였고, 관광지는 15·16위 두 자리뿐이었다 —
그 두 자리가 바로 하한이 밀어 넣은 것이다.

상한이 예전에 있었다가 빠진 이력이 있다(`selectTopDiverse` 주석). 두 가지가 잘못이었다:

1. 상한에 걸린 후보를 **버렸다** — 제주에서 3위 한라산·5위 비자림이 사라졌다
2. 제약을 **머리에 걸어서** 상위 6칸 구성을 흔들었다

그래서 이번 상한은 둘을 피한다 — 채울 관광 후보가 없으면 상한을 포기하고, 깎는 자리는 항상 꼬리다.
점수 순서 자체는 건드리지 않는다.

## 3. 스윕

`CRAG_POOL_MAX_DINING_RATIO` 로 노출해 한 프로세스 안에서 쟀다.

| 비율 | 희소 카탈로그 R\|cat | 조밀 카탈로그 R\|cat |
| --- | --- | --- |
| 1 (상한 없음) | 0.471 | 0.439 |
| 0.625 | 0.471 | 0.439 |
| 0.5 | 0.471 | 0.444 |
| **0.375** | **0.475** | **0.458** |
| 0.25 | 0.475 | 0.463 |

희소 카탈로그(현재 45,716행)에서 **움직이는 케이스는 `daegu-nostalgic` 하나뿐**이다 (0.231 → 0.308).
연속 A/B 로 재현 확인했다. 나머지 15개는 소수점까지 동일하다 — 상한이 안 걸린다는 뜻이고,
지금 카탈로그에선 식음이 풀을 지배하지 않는다는 뜻이기도 하다.

조밀 카탈로그(부산 +4,036행)에선 세 케이스가 움직인다:

| 케이스 | 상한 없음 | 0.375 | 0.25 | (희소 기준값) |
| --- | --- | --- | --- | --- |
| busan-beach | 0.00 | 0.15 | 0.15 | 0.31 |
| daegu-nostalgic | 0.23 | 0.31 | 0.31 | 0.23 |
| seomyeon-station-anchor | 0.31 | 0.38 | 0.46 | 0.42 |

## 4. 0.25 가 아니라 0.375 를 쓴다

지표만 보면 0.25 가 조밀 카탈로그에서 조금 낫다. 그래도 안 쓴다.

후보 풀 크기는 `일정 항목 수 + 4` 다(`PlannerService`). 3일 여행이면 limit 19 이고, 0.25 는
식음 후보 4개로 6끼를 채워야 한다. **골든셋 정답에는 식당이 거의 없어 지표는 언제나 식음을 줄이는
쪽을 가리킨다** — 여기서만은 지표가 아니라 일정이 실제로 필요로 하는 슬롯 수를 따른다.
0.375 는 희소 카탈로그 이득을 온전히 가져가면서(0.25 와 동일) 16칸 중 6칸을 식음에 남긴다.

## 5. 상한으로도 조밀 적재는 아직 이르다

상한을 켠 채로 비교해도 조밀 적재는 여전히 손해다.

| | 희소 + 상한 | 조밀 + 상한 |
| --- | --- | --- |
| R@10 | 0.401 | 0.399 |
| R\|cat | 0.475 | 0.458 |
| MRR | 0.700 | 0.688 |
| 커버리지 | 97% | 98% |

busan-beach 가 0.15 로 희소 기준(0.31)의 절반이다. 상한은 풀 **구성**을 고치지만, 정답이 pgvector
선발 단계에서 이미 밀린 건 못 되돌린다 — 풀에 없는 걸 상한이 끌어올 수는 없다.
그래서 조밀 적재 행은 이번에도 되돌렸다(카탈로그 45,716행 유지).

## 6. 남은 것

- **선발 단계가 다음 병목이다.** 상한은 뽑힌 16개의 구성만 고친다. `PLACE_CANDIDATE_POOL_MULTIPLIER`
  (현재 20)로 뽑는 pgvector 풀 자체에서 정답이 밀리면 손쓸 방법이 없다 — 조밀 적재를 켜려면
  여기를 먼저 봐야 한다
- `seoul-city-nightview`(R\|cat 0.30)는 이번 상한으로 안 움직였다. 다른 원인이다
- [kakao-category-search-ceiling-v1.md](kakao-category-search-ceiling-v1.md) §6 의 항목들은 그대로 남아 있다
