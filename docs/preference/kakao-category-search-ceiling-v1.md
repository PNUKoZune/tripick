# 카카오 카테고리 검색 45건 상한과 앵커 격자 v1

KTO 일일 한도가 리셋돼 밀려 있던 `category_detail` 백필을 끝냈다. 백필 자체는 **랭킹 중립**이었고,
그 뒤 커버리지 미달 정답 3건을 추적하다 카카오 적재의 구조적 상한을 찾았다 —
**카테고리 검색은 한 질의당 45건이 끝이고, 그 45건은 거리순이라 반경을 넓혀도 3km 에서 끊긴다.**

전제 — [kakao-source-enrichment-v1.md](kakao-source-enrichment-v1.md) §10 에서 남긴 두 항목
(잔여 백필 / 전국 카카오 보강)의 후속이다.

## 1. `category_detail` 백필 — 완료, 랭킹 중립

`KTO_FETCH_OPENING_HOURS=false` 로 16개 시도 35,442건을 다시 훑었다. KTO 의 `category_detail` 은
`contentTypeId` 이름 매핑이라 `areaBasedList2` 페이지만으로 채워진다 — `detailIntro2` 추가 호출이 없다.

| | 백필 전 | 백필 후 |
| --- | --- | --- |
| `category_detail` 보유 (KTO) | 398행 | **33,733행** (결측 62) |
| R@5 | 0.239 | 0.233 |
| R@10 | 0.408 | 0.401 |
| R\|cat | 0.471 | 0.477 |
| MRR | 0.700 | 0.700 |

전부 노이즈 폭(±0.013) 안이다. **예상된 결과다** — `category_detail` 은 임베딩 텍스트에 안 들어가
재임베딩이 없었고(유지 33,679행), 검색에선 `isEligibleItineraryCandidate` 의 입력으로만 쓰인다.

실제로 판정이 뒤집힌 행은 **전 카탈로그에서 5건**이었다. 여행 카테고리 화이트리스트가 이름 검사를
건너뛰게 하므로, 이름에 의료 키워드가 든 행이 살아난다:

| 살아난 것 (맞음) | 들어온 것 (틀림) |
| --- | --- |
| 부산 구 백제병원 (등록문화재, 관광지) | 이문원한의원 (KTO 가 관광지로 줌) |
| 서울대학교병원 의학박물관 (문화시설) | 더바디성형외과의원 (KTO 가 관광지로 줌) |
| 안의원조갈비집 (음식점) | |

2행 오염 대 3행 구제라 **코드로 쫓지 않았다.** 끝문자 기준 거부로 바꾸면 한의원·성형외과의원은
잡지만 '부산 구 백제병원'이 같이 죽는다 — 실익이 1행이라 규칙을 늘릴 값이 아니다.

정리 CLI dry-run 은 전 부류 합계 1건(중복 1쌍)이었다. 카탈로그가 게이트와 정합한 상태라는 뜻이다.

## 2. 카카오 카테고리 검색은 45건에서 끝난다

커버리지 미달 정답 3건을 카카오에 직접 물었다:

| 정답 | 카카오 | 판정 |
| --- | --- | --- |
| 경주밀레니엄파크 | `신라밀레니엄파크` 로 존재, **이미 카탈로그에 있음** | 골든셋 정답 이름이 틀렸다 |
| 자만벽화마을 | 존재하나 `category_group_code` 가 **빈 값** | 카테고리 검색으로는 영원히 못 잡는다 |
| 전리단길 | `AT4`, 반경 500m 검색이면 나옴 | 잡혔어야 하는데 안 잡혔다 |

세 번째가 실마리였다. 전포동 중심 `AT4` 실측:

| 반경 | `total_count` | `pageable_count` | 실제 도달 |
| --- | --- | --- | --- |
| 2,000m | 33 | 33 | 33건 |
| 5,000m | 109 | **45** | 45건 |
| 10,000m | **378** | **45** | 45건 (거리 0~3.6km) |

`page=4` 는 에러가 아니라 **3페이지를 그대로 다시 준다.** 즉 상한은 45건 = 3페이지다.
코드는 `KAKAO_MAX_PAGE = 45` 를 "최대 페이지"로 알고 있었다 — 675건을 가져올 수 있다고 믿은 것이다.

결과가 거리순이라 더 나쁘다. **반경 10km 로 넓혀도 실제로 걷히는 건 반경 3.6km 원 하나다.**
앵커를 0.1°(≈11km) 격자로 놓았으니 앵커와 앵커 사이가 통째로 안 걷혔다. 직전 카카오 보강이
5,266행을 넣고도 정답을 1개밖에 못 늘린 이유가 이것이다.

## 3. 고친 것 — 격자를 반경에 묶었다

- `KAKAO_CATEGORY_MAX_RESULTS = 45` 로 실측 근거와 함께 상한을 바로잡았다 (`KAKAO_MAX_PAGE` 는 파생값)
- `deriveAnchors` 의 격자를 하드코딩 `toFixed(1)` 대신 **적재 반경에서 파생**시켰다
  (`ANCHOR_GRID_DEGREES_PER_METER = 1/100000` → 반경 10km 에서 0.1°, 종전과 동일)

반경만 줄이면 격자가 0.1° 로 남아 앵커가 여전히 11km 씩 떨어진다. 둘은 같이 움직여야 원이 맞물린다.

## 4. 부산 실측 — 커버리지는 올랐고 랭킹은 무너졌다

반경 3,000m · 앵커 120곳으로 부산만 다시 적재했다.

| | 종전 (10km/24곳) | 조밀 (3km/120곳) |
| --- | --- | --- |
| 수집 | 1,267건 | **8,466건** |
| 신규 행 | — | 4,036 |
| 전리단길 | 없음 | **진입** |
| 적재 커버리지 (전체) | 97% | **98%** |
| seomyeon-station-anchor 커버리지 | 92% | **100%** |
| busan-beach R@10 | 0.31 | **0.00** |
| busan-beach MRR | 0.33 | **0.00** |
| 전체 R@10 | 0.401 | 0.382 |

busan-beach 가 0.00 이다. 정답 13개(해운대·광안리·송정·다대포…)가 **전부 카탈로그에 있는데도**
상위 16위 안에 하나도 없다. 상위는 `해적`·`바다향`·`바다횟집`·`뉴부산횟집` 같은 횟집·카페였다.

원인은 신규 4,036행의 구성이다 — restaurant 2,915 + cafe 1,565 대 attraction 1,463.
카카오 카테고리 검색은 어디를 찍어도 `FD6`·`CE7` 이 45건 상한을 채우지만 `AT4`·`CT1` 은 그만큼 없다.
그래서 조밀하게 훑을수록 **음식 비중이 구조적으로 커진다.** '바다'·'해'가 든 상호가 해변 질의의
retrieval·taste 를 가져가고, 정답은 pgvector 단계에서 이미 밀린다.

인지도가 구제하지 못하는 이유도 여기 있다. 인지도는 pgvector 가 좁힌 후보 집합 위에 얹히는데,
정답이 그 집합에 없으면 붙을 자리가 없다. 실제로 busan-beach 후보 16개의 popularity 가
**전부 중립 0.50** 이었다(직전 실행은 15/16 이 비중립, 최대 1.00) — 코퍼스에 언급되는 후보가
하나도 없었다는 뜻이다.

> 하네스 관찰: popularity 가 전 후보 중립이면 "인기 신호 실패"와 "정답이 후보에 없음"이 같은 모양으로
> 보인다. daegu-nostalgic 도 두 실행 모두 0/16 중립이다 — 이 케이스의 오래된 부진과 같은 뿌리일 수 있다.

## 5. 실험 행은 되돌렸다

4,036행을 삭제해 카탈로그를 45,716행으로 복원했고, 재측정으로 지표가 돌아온 것을 확인했다
(R@5 0.228 / R@10 0.401 / R\|cat 0.477 / 97% / MRR 0.700).

되돌린 이유 — 커버리지 +1%p 와 busan-beach 0.31→0.00 을 맞바꾸는 건 이 브랜치가 혼자 정할 문제가
아니다. 코드 수정(§3)은 그 자체로 옳으므로 남겼다. 복구는 같은 명령 재실행이면 된다:

```bash
KAKAO_INGEST_RADIUS_M=3000 KAKAO_INGEST_MAX_ANCHORS=120 \
  pnpm ingest:places -- --regions=부산 --sources=kakao --max=25000
```

## 6. 남은 것

- **조밀 적재를 켤지는 결정 사항이다.** 켜려면 음식 비중 문제를 먼저 풀어야 한다 — 앵커별 카테고리
  할당량으로는 안 된다(음식이 실제로 그만큼 많다). 질의 의도(해변·야경 vs 맛집)가 랭킹에 반영돼야 한다.
  이건 [kakao-source-enrichment-v1.md](kakao-source-enrichment-v1.md) 의 체인 지점 발견과 같은 패턴이다 —
  카카오 음식 물량이 늘 때마다 관광 의도 케이스가 깨진다
- **골든셋 교정 1건**: `경주밀레니엄파크` → `신라밀레니엄파크` (이미 카탈로그에 있는데 이름이 달라 미달로 잡힌다)
- **`자만벽화마을` 류는 카테고리 검색으로 못 잡는다.** `category_group_code` 가 빈 문서는 키워드 검색
  경로가 따로 있어야 한다
- 카카오 행 4,345개가 아직 `category_detail` 결측 (컬럼 도입 전 적재분)
- 하네스 정답 매칭(부분 문자열) 교정은 여전히 미수정 — [kakao-source-enrichment-v1.md](kakao-source-enrichment-v1.md) §9
