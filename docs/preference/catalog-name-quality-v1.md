문서 목적: 장소 카탈로그(`place_embeddings`)에 **장소가 아닌 행**이 들어오던 두 경로(일반어 상호·SEO 상호·여행코스 기사)를 막은 규칙과, 규칙을 그렇게 좁힌 실측 근거를 고정한다.

작업 브랜치: `feat/catalog-name-quality`
작성일: 2026-07-28
관련 문서: [`retrieval-ranking-tuning-v1.md`](./retrieval-ranking-tuning-v1.md) (직전 작업 · 인지도 매칭), [`popular-place-ingestion-v1.md`](./popular-place-ingestion-v1.md) (popular 적재 관문), [`place-retrieval-region-filter-and-eval-v1.md`](./place-retrieval-region-filter-and-eval-v1.md) (평가 하네스), [`naver-popularity-signal-v1.md`](../planner/naver-popularity-signal-v1.md) (인지도 신호 원본)

## 1. 배경 / 문제

백로그 두 항목을 함께 처리했다. 둘 다 "이름이 장소 같지 않은 행이 상위를 먹는다"는 같은 증상인데 유입 경로가 다르다.

- **popular 패스가 짧은 일반어 상호를 통과시킴** — 광주 적재분에 `다른`·`이유`·`이젠`·`조금더`. 카카오에 실존 등록 상호이고 코퍼스에도 그 단어가 있어 두 관문을 정당하게 통과한다.
- **카탈로그의 SEO 상호·여행코스 글 행** — `경주맛집`(인지도 1.00 으로 경주 케이스 2위)과, KTO 여행코스로 내려오는 큐레이션 기사(`가정의 달, 싱글을 위한 혼자 먹는 밥상 코스`)가 장소로 적재돼 있었다.

### 1.1 먼저 "무엇이 실제로 오염인지" 를 셌다 (10,608행)

규칙을 정하기 전에 카탈로그를 직접 세지 않으면 접미사 규칙 같은 걸 만들어 실제 장소를 대량으로 잃는다.

| 관측 | 건수 | 판단 |
| --- | --- | --- |
| 2글자 일반어 상호(`다른`·`이유`·`이젠`) | — | **이미 막혀 있었다** — 직전 랭킹 튜닝의 `MIN_COUNTABLE_LENGTH=3` 이 관문 ②에서 언급 0 으로 떨어뜨린다 |
| 3글자 이상 일반어 상호(`조금더`·`맛있게`·`내안에`·`네이버`) | — | 남은 구멍. 코퍼스 매칭이 공백을 제거한 문자열이라 본문 '조금 더'가 이름 `조금더`에 걸린다 |
| 단일 어절 + 길이 ≤6 + SEO 접미 | **7건** | 전부 참 — `경주맛집`·`다솥맛집`·`감내맛집`·`갯마을맛집`·`벽계수맛집`·`기차여행`·`곳` |
| `…코스`·`…여행` 접미 | 80건 | **대부분 실제 장소** — `해파랑길 2코스`·`금정산둘레길 6코스`·`경기둘레길 가평20코스` |
| 주소가 빈 문자열 | 110건 | 표본 전수가 KTO 여행코스 기사 |
| 어절 4개 이상 + 조사/문장부호 (주소 있는 행) | 38건 | **절반이 실제 명소** — `경산 임당동과 조영동 고분군`·`강진 병영마을 옛 담장`·`경주 양동마을 [유네스코 세계유산]` |

마지막 두 줄이 이 작업의 방향을 정했다. **이름 모양만으로는 기사와 명소를 가를 수 없다** — 그래서 여행코스는 KTO 에 되물어 `contentTypeId=25` 를 확정한 뒤에만 이름 규칙을 적용하고, SEO 상호는 오탈락 0 을 확인한 좁은 조건("단일 어절 + 짧은 이름")으로만 판정한다.

## 3. 지역 특이도 (관문 ③)

### 3.1 왜 길이·사전이 아니라 대조 코퍼스인가

인지도 신호는 "깨끗한 후보 name 이 코퍼스에 몇 번 나오나" 를 세는 역방향 매칭이다. 그 대가로 **이름이 흔한 한국어 단어인 상호가 남의 문장을 자기 언급으로 가져간다.** 길이 하한은 답이 아니다 — 3글자 이하 이름이 1,487행이고 대부분 `가우도`·`무등산`·`죽녹원`·`거문도` 같은 실제 명소다. 일반어 사전을 손으로 유지하는 것도 끝이 없다(카페 `담다`·`연다`·`티내다` 가 전부 같은 부류다).

일반어에는 구조적 특징이 있다. **어느 지역 코퍼스에서나 비슷한 비율로 나온다.** 실제 장소는 자기 지역 코퍼스에만 몰린다. 그래서 지역명이 없는 전국 추천 코퍼스(`국내 여행지 추천`·`국내 맛집 추천`·`가볼만한 곳 추천`)를 대조군으로 두고 언급률 비를 본다.

```
지역 특이도 = (지역 코퍼스 언급 수 / 지역 문서 수) / (대조 코퍼스 언급 수 / 대조 문서 수)
대조 코퍼스에 없는 이름 = Infinity (그 지역에서만 쓰이는 고유명)
```

### 3.2 임계 5 의 근거 (실측)

제주·대구·광주 × 명소·맛집 축, 코퍼스 각 600문서, 대조 600문서:

| 이름 | 축 | 지역 언급 | 대조 언급 | 특이도 |
| --- | --- | --- | --- | --- |
| 팔공산 · 서문시장 · 돈사돈 · 따로국밥 · 우진해장국 | 명소·맛집 | 1~30 | 0 | ∞ |
| 한라산 | 제주 명소 | 19 | 2 | 9.50 |
| 성산일출봉 | 제주 명소 | 37 | 4 | 9.25 |
| 성산일출봉 | 제주 맛집 | 24 | 4 | 6.00 |
| **맛있게** | 대구 맛집 | 12 | 3 | **4.00** |
| **네이버** | 제주 맛집 | 10 | 3 | **3.33** |
| **조금더** | 제주 맛집 | 1 | 2 | **0.50** |

두 무리 사이가 4~6 에서 비어 있어 **5** 를 뒀다(`NAVER_MIN_REGION_SPECIFICITY`). 실제 장소의 최저가 6.00, 일반어의 최고가 4.00 이다.

### 3.3 적용 지점 두 곳

- **적재** — `PopularPlaceService.verify` 의 관문 ③. 대조 코퍼스 수집이 실패하면 이 관문만 건너뛴다(적재를 멈출 이유가 아니다). 탈락 사유는 `일반어` 계수로 지역·축별 로그에 남는다.
- **런타임 랭킹** — `getPopularityIndex` 가 지역 인덱스를 `RegionSpecificPopularityIndex` 로 감싼다. 특이도 미달이면 **중립(0.5)** 이다. 감점(0.15)이 아닌 이유는 그 자리가 '언급 없는 마이너 장소' 의 의미로 이미 쓰이고 있어서다. 대조 코퍼스는 목적지와 무관해 캐시 1건으로 전 목적지가 공유한다(6h 당 6콜).

## 4. 짧은 이름 공백 매칭

`compact` 매칭(공백 제거)은 '동궁과 월지'↔'동궁과월지' 를 흡수하려고 넣은 것인데, 짧은 이름에선 공백을 건너뛰어 남의 문장을 자기 언급으로 만든다(광주 식당 `조금더` ← 본문 '조금 더'). 3글자 이하는 공백을 살린 코퍼스에서만 센다 — 3글자 명소(한라산·불국사·석굴암)는 블로그에서도 붙여 쓰므로 손실이 없다.

공백 매칭으로는 0 인데 compact 로는 걸리는 이름은 **판정 보류(중립)** 다. 감점까지 주면 띄어 쓴 실제 짧은 이름이 손해를 본다 — 2글자를 중립으로 두는 기존 판단과 같은 이유다.

## 5. SEO 상호 · 여행코스 기사 판별

[place-name-quality.ts](../../apps/api/src/planner/retrieval/place-name-quality.ts) 두 함수. 판정 근거를 한 곳에 모아 적재·검색·정리 스크립트가 같은 규칙을 쓴다.

**`isSeoBusinessName`** — 단일 어절 + 공백 제거 길이 ≤6 + SEO 접미(`맛집|여행|관광|명소|핫플|추천|코스|곳|장소`). 접미사만 보면 코스명 80건이 함께 죽으므로 "단일 어절" 이 핵심 조건이다. 검색 단계([place-eligibility.ts](../../apps/api/src/planner/retrieval/place-eligibility.ts))에도 넣었다 — 실존 음식점이라 카테고리 화이트리스트로는 안 걸리고, 정리 스크립트를 아직 돌리지 않은 환경이 있다.

적재는 **소스 합류 후 한 곳에서** 막는다. popular 관문이 막아도 카카오 주변 카테고리 검색이 `경주맛집` 을 실존 음식점으로 다시 주워 오기 때문이다.

**`isTravelCourseArticle`** — 호출 측이 `contentTypeId=25` 를 확인한 뒤에만 쓴다. 주소 없음 / 문장부호 / 어절 4개 이상 / 조사·연결어미로 끝나는 어절. 물결(`~`)은 문장부호에서 뺐다 — `비학산~금병산누리길 2코스` 처럼 실제 코스명이 구간 표기로 쓴다.

## 6. 정리 스크립트

`pnpm cleanup:catalog`(dry-run) / `-- --apply`. **마이그레이션이 아닌 이유** — 삭제는 스키마가 아니라 데이터 청소이고, 같은 행은 적재를 다시 돌리면 되살아난다. 재발 차단은 위 게이트가 정본이고, 스크립트는 게이트가 생기기 전에 들어온 행만 걷어낸다.

여행코스 단계는 KTO 에 시도별 `areaBasedList2 contentTypeId=25` 를 되물어 contentId 확정 집합을 만든 뒤(전국 1,040건) 카탈로그와 교차한다. 적재 행이 `contentTypeId` 를 저장하지 않아 이름만으로는 기사와 명소를 못 가르기 때문이다.

로컬 실행 결과 (10,608행):

```
[SEO 상호] 7건
[course] KTO 여행코스 contentId 1040건 중 카탈로그에 있는 행 120건
         → 기사 120건 삭제 / 실제 코스명 0건 유지
삭제 합계 127건 → 10,481행
```

`해파랑길 2코스` 류 42건은 **contentTypeId 25 가 아니어서** 교차 집합에 애초에 들어오지 않았다(코스 기사만 25로 내려온다). 삭제 후 `주소 빈 행 0`·`…맛집 접미 0`·코스명 42건 유지 확인.

## 7. 검증

`pnpm eval:retrieval` 골든셋 11케이스, 같은 날 전후 측정:

| 지표 | 전 | 후 |
| --- | --- | --- |
| recall@5 | 0.186 | **0.195** |
| recall@10 | 0.317 | **0.326** |
| 카탈로그내 recall(R\|cat) | 0.498 | **0.505** |
| MRR | 0.705 | **0.720** |
| 적재 커버리지 | 81% | 81% |
| 지역정합 / 금지어 | 100% / 0 | 100% / 0 |

케이스별로는 경주 `recall@10` 0.50→0.60, 여수 `R|cat` 0.63→0.75, 광주 0.33→0.44, 강릉 MRR 0.33→0.50 이 올랐고 **서울만 `R|cat` 0.50→0.33 으로 내려갔다** — 한강공원이 상위 16 밖으로 밀렸다. 서울은 660행이라 후보 풀(limit×10=160)이 상한으로 걸리는 지역이고, 기사 행이 사라지자 그 아래에 있던 다른 행들이 풀에 새로 들어와 순위가 재배치된 것이다. 인지도 항은 전후 동일(중립 8/176, 가점 166/176)이라 특이도 필터 때문이 아니다.

테스트 541개 통과(신규 spec [place-name-quality.spec.ts](../../apps/api/test/planner/retrieval/place-name-quality.spec.ts), 인지도 매칭·특이도 케이스는 [naver-search.service.spec.ts](../../apps/api/test/planner/retrieval/naver-search.service.spec.ts), 관문 ③은 [popular-place.service.spec.ts](../../apps/api/test/planner/retrieval/popular-place.service.spec.ts)).

## 8. 한계 · 후속

- **전국적으로 유명한 장소는 특이도가 낮아질 수 있다.** 대조 코퍼스가 전국 추천 글이므로, 그 글에서 자주 언급되는 최상위 명소는 비가 작아진다. 실측 최저가 6.00 이라 임계 5 와 여유가 크지 않다 — 코퍼스가 계절에 따라 흔들리면 재측정이 필요하다.
- **일반어 상호 행 자체는 지우지 않았다.** `이유`·`지금`·`공간` 은 실존 식당·카페이고 카카오 소스로도 정당하게 들어온다. 해로운 건 존재가 아니라 인지도 가점이라, 랭킹에서 중립화하는 것으로 끝냈다.
- 세종 `sigungu_code` 44건 오류(옛 백필 SQL)는 이 작업 범위 밖이다 — 검색 영향이 없어 백로그에 남긴다.
- 카탈로그에 `source`·`contentTypeId` 를 저장하면 정리·감사가 KTO 재조회 없이 가능해진다. 다음 재적재 때 컬럼을 추가할지는 별건.
