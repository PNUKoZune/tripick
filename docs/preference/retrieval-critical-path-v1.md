# AI 검색 임계 경로 병렬화·관측성 v1

## 변경 전

한 번의 장소 검색에서 네이버 인기도, 목적지 앵커, 질의 임베딩을 차례로 기다렸다. 네이버 내부도
지역 코퍼스 뒤에 전국 대조 코퍼스를 받고, 검색어 세 개를 직렬로 처리했다. 캐시가 빈 순간 같은
목적지 요청이 겹치면 각 요청이 동일한 외부 호출을 다시 만들었다.

## 변경 후

- 인기도·앵커·임베딩을 `Promise.all`로 동시에 시작한다.
- 지역·전국 대조 코퍼스를 동시에 만들고, 검색어는 설정 가능한 제한 동시성으로 처리한다.
- 네이버 인덱스와 목적지 앵커에 in-flight request coalescing을 적용한다.
- 응답 trace와 구조화 로그에 popularity, anchor, embedding, seed, pgvector, Kakao, rerank,
  total 시간을 밀리초 단위로 남긴다.

병렬 단계의 시간 합은 전체 시간보다 클 수 있다. 성능 전후 비교는 warm/cold를 나누고 p50/p95로
기록하며, 외부 API 결과가 바뀌는 검색 품질 지표와 지연 지표를 같은 수치로 해석하지 않는다.

`NAVER_SEARCH_CONCURRENCY` 기본값은 2다. 한 검색어 안에서 blog+cafe 두 요청이 동시에 실행되므로
한 코퍼스의 최대 동시 HTTP 요청은 기본 4개다. 허용 범위는 1~4로 제한한다.
