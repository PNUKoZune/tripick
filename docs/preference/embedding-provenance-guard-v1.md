# 임베딩 벡터 공간 무결성 가드 v1

## 문제

원격 임베딩 서버가 실패하면 `TextEmbeddingService`는 같은 차원의 결정적 해시 벡터를 만든다.
차원만 검사하면 해시·BGE 또는 서로 다른 BGE 버전이 같은 공간인 것처럼 코사인 비교되어, 오류 없이
개인화 순위만 오염된다.

## 런타임 규칙

- 모든 임베딩 결과는 `source`와 `modelId`를 함께 가진다.
- 일반 취향 수정 중 해시 폴백이 발생하면 취향 원문만 저장하고 마지막 정상 원격 벡터는 유지한다.
- 취향 검색은 현재 `LLM_EMBEDDING_MODEL`과 일치하며 `source=remote`인 벡터만 읽는다.
- 질의 임베딩이 해시면 pgvector를 호출하지 않고 카카오·시드 폴백으로 내려간다.
- 장소 검색도 현재 질의 모델과 같은 `embedding_model` 행만 사용한다.
- 자동 seed 적재는 원격 임베딩만 허용하고 모델 provenance를 함께 저장한다.

## 배포

마이그레이션 이전의 취향 행은 출처와 모델을 증명할 수 없어 자동으로 backfill하지 않는다. 배포 후
원격 임베딩 서버가 정상인 상태에서 다음 명령으로 다시 만든다.

```bash
pnpm --filter @tripick/api reembed:preferences
```

장소 모델을 교체했다면 장소와 취향을 반드시 같은 모델로 함께 재임베딩한다. 모델 불일치 동안에는
벡터 검색이 의도적으로 폴백하므로 잘못된 순위를 정상 응답으로 내보내지 않는다.
