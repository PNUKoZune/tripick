# 그룹 취향 공정성 랭킹 v1

## 문제

여행에 여러 멤버가 있어도 일정 생성과 대안 추천은 `trip.userId`의 취향 태그·벡터만 읽었다.
화면의 “멤버 취향 조율”은 투표를 보여줄 뿐 실제 CRAG 후보 검색과 연결되지 않았다. 또한 새 여행은
동행자를 저장하기 전에 일정 생성을 끝내므로, 그룹 로직을 검색에 붙이기만 해도 최초 일정에는
절대 반영될 수 없는 순서였다.

단순히 멤버 벡터 평균만 사용하는 것도 충분하지 않다. A와 매우 잘 맞고 B와 강하게 충돌하는 장소가
평균으로 살아남아, 한 사람을 계속 소외시키는 일정이 될 수 있다.

## 적용 범위와 동의 경계

- 여행 owner는 과거 `trip_members` owner 행이 없어도 항상 포함한다.
- `accepted` 멤버만 포함한다. 계정 초대가 `pending`인 동안에는 해당 사용자의 최신 프로필과 벡터를
  그룹 검색에 사용하지 않는다.
- 계정이 없는 수동 동행자는 여행에 명시 저장된 `preferenceTags`만 사용하며 개인 벡터는 없다.
  구성원별 태그 점수에도 같은 평균+최저 공정성 식을 적용하므로 벡터가 없어도 소외 검사는 된다.
- 같은 계정의 owner/member 행이 중복돼도 한 번만 센다.

프로필과 벡터는 멤버별 N+1 조회 대신 각각 한 번의 배치 조회로 가져온다. 저장된 벡터 차원이 섞여
있으면 가장 많은 차원(동률이면 owner 차원)만 사용하고 제외 수를 경고 로그로 남긴다.

## 두 단계 그룹 검색

### 1. 후보 검색: normalized centroid

같은 차원의 구성원 벡터를 평균한 뒤 L2 정규화한다.

```text
centroid = normalize((v1 + v2 + ... + vn) / n)
search = blend(destination_query, centroid)
```

이 벡터로 pgvector KNN 후보를 찾는다. 구성원마다 별도 KNN을 실행해 합치는 방식과 달리 후보 검색은
한 번이라 멤버 수에 따라 DB round-trip이 늘지 않는다.

### 2. 공정성 재랭킹: 평균 + least-member

같은 SQL에서 각 후보와 모든 구성원 벡터의 코사인 유사도 배열을 계산한다. CRAG는 이를 0~1로
정규화하고 다음 점수를 취향 항에 넣는다. 후보 태그도 구성원별로 따로 채점해 같은 공정성 식을
적용하므로 수동 동행자와 아직 임베딩이 없는 계정도 태그 범위에서 참여한다.

```text
group_personalization = (1 - λ) × mean(member_scores) + λ × min(member_scores)
λ = CRAG_GROUP_LEAST_MISERY_WEIGHT (기본 0.35)
```

`λ=0`은 다수 평균만 보고, `λ=1`은 가장 낮은 한 사람만 본다. 기본값은 평균 효용을 주축으로 두되
최저 구성원이 실제 순위를 움직이게 하는 절충값이다. 운영 확정값으로 과장하지 않고 그룹 평가의
average/least NDCG, member coverage, disparity를 함께 보며 조정한다.

후보 trace에는 전체 그룹 멤버 수와 실제 벡터가 있는 멤버 수를 나눠 기록한다. 후보 reason에는
그룹 벡터가 적용된 경우 최저 만족도를 표시해 랭킹 근거를 추적할 수 있다.

## 최초 생성 순서

`TripsService.create`에 내부 `beforeGenerate` 훅을 두고 Main planner가 초대/수동 멤버를 먼저 저장한
후 `generateItinerary`를 호출한다.

```text
trip + trip_days 저장
  → 동행자 저장 (pending/accepted 판정)
  → 그룹 프로필 배치 조회
  → 그룹 후보 검색·공정성 재랭킹
  → 일정 저장
```

동행자 준비나 일정 생성이 실패하면 기존과 같이 trip을 삭제하고 cascade로 멤버·일차도 정리한다.
직접 `/trips` API를 쓰는 owner-only 생성은 훅 없이 기존 동작을 유지한다.

## 검증 시나리오

- 평균 코사인이 더 높지만 한 멤버가 강하게 싫어하는 후보보다 모두에게 균형인 후보가 먼저 온다.
- pending 멤버는 테스트 더블이 잘못 반환해도 방어적으로 제외된다.
- 수동 멤버 태그는 합쳐지지만 vector member count에는 포함되지 않는다.
- 서로 다른 벡터 차원이 섞여도 pgvector 검색 전체가 실패하지 않는다.
- 그룹 벡터 배열을 한 SQL에서 계산하고 결과 후보에 보존한다.
- 최초 생성에서 멤버 저장이 planner 호출보다 먼저 실행되고, 준비 실패 시 trip이 롤백된다.

## 후속 측정

paired persona 골든셋에서 centroid 기준선과 이 랭커를 동일 후보 풀로 비교한다. 평균 NDCG만 올리는
변경은 채택하지 않고, least-member NDCG와 member coverage가 함께 유지·개선되는지 확인한다.
